## 1. 何のアプリか
- **日付印（丸の中を3段に分けた「部署名／日付／氏名」の印影）を作る小さな Windows アプリ。** 印影をクリックすると、指定サイズの PNG でクリップボードにコピーされ、Word・Excel などに貼れる。上段・下段の文字とサイズ、出力サイズを保存できる。
- 技術: **Tauri v1.2**（Rust）＋ Svelte 3 ＋ Vite 4 ＋ Tailwind／Skeleton。SVG を canvg で PNG にし、`navigator.clipboard` でコピーする。
- 規模: App.svelte が約5KB、main.rs は save／load の2コマンドだけ。公開リポジトリ。Cargo.toml は MIT だが、LICENSE ファイルはない。
- 履歴: コミットは5件で、2023-03-22 07:34〜2023-03-23 08:31 JST の間だけ。README は「個人的に練習用で作成」。
- **完成度: 試作段階**（動く最小限）。

**現状の問題点（Store に出す前に直すもの）**
| 問題 | 影響 |
|---|---|
| 設定 `Setting.json` を**カレントディレクトリ**に読み書きしている（リポジトリにも同梱） | MSIX ではインストール先が書き込み不可なので**保存に失敗する**。%APPDATA%（Tauri の app_config_dir）へ移す |
| フォントを **Google Fonts から実行時に読み込む**（Shippori Mincho B1） | オフラインだと書体が変わる。外部通信がありプライバシーポリシーの説明が要る。→ フォントを同梱する（OFL の想定。**ライセンス要確認**） |
| `allowlist: all`、`csp: null`、`api-all` | 権限が過剰。審査上も安全上も最小権限にする |
| identifier が `tyaromax` | 逆ドメイン形式（例: `jp.tyaro.estamp`）に直す。MSIX の名前・Publisher と合わせる |
| 日付は西暦 `yyyy.mm.dd` 固定で、日付欄を編集しても保存されない。中段の文字サイズを変えられない | 機能不足 |
| 画面 250×120 の固定、トーストが英語、雛形の Greet.svelte が残っている、clipboard プラグインは実質使っていない | 整理が必要 |
| Tauri v1 | 製品群（Banto）は v2。**練習の成果を流用するには v2 に移行**すべき |

## 2. Store 練習用としての評価（結論: **向いている。無料で出すのに最適**）

| 観点 | 評価 |
|---|---|
| MSIX 化のしやすさ | ◎ サービス・昇格・%ProgramData%・ネットワーク待ち受けのどれもない。直すのは設定の保存先と外部フォントだけ |
| 審査の通しやすさ | ◎ PLC などの機器が不要で、審査員がそのまま全機能を試せる。restricted capability も不要 |
| 商標・他社との関係 | ○ 他社製品に依存しない。注意点は次の3つ |
| ライセンスの練習 | ○（一部は△）。下に記載 |

**商標・他社との関係で注意すること**
- 他社の商標（シヤチハタなど）を名前・説明・検索語に使わない。Word／Excel は「貼り付け先の例」として書く程度にする。
- 掲載文で「**法的効力・本人確認・改ざん防止はない**」と明記する（画像の印影であるため。Store ポリシー 10.1.1 の「機能を正確に記述」）。実印の画像化をうたう機能は入れない。
- 書体を同梱する場合は、その書体のライセンス表示を入れる。

**ライセンスの練習としてできること**
- **できる**:
  - MSIX 化（winapp CLI）、Partner Center での名前予約・提出・審査・更新配信
  - `StoreContext` の初期化（デスクトップアプリでは `IInitializeWithWindow` によるウィンドウ関連付けが必要）
  - `GetAppLicenseAsync` によるライセンスの読み取り
  - **買い切りアドオン（durable）の購入**（`RequestPurchaseAsync`）と、購入済みの判定
  - 例: 無料本体に「プロ機能アドオン」（和暦・複数印影・PNG 保存など）を 160〜300円程度で付ける。手数料15%。
- **できない・制約がある**:
  - **時間制限付き試用（`IsTrial`）は有料アプリでしか設定できない**ので、無料の estamp では本番どおりには試せない。→ PLC タグ・モニタの最初の提出を「非公開（直接リンクのみ）」にして、そこで検証するのが現実的。
  - アドオンの購入テストに、プロモーションコードや返金が使えるかは**要確認**。
- **成果物の流用**: Store ライセンスの処理を **Rust の共通モジュール**（例: `banto-store-license`）として作れば、PLC タグ・モニタにそのまま移せる。

## 5. PLC タグ・モニタとの役割分担（提案）

| | estamp（無料） | PLC タグ・モニタ（有料） |
|---|---|---|
| 目的 | Store の手順を一通り通す練習台、開発者アカウントの実績づくり | 収益化の本番 |
| 練習・検証すること | MSIX 化、名前予約、提出・審査・更新、プライバシーポリシー、`StoreContext`、**買い切りアドオンの購入** | **時間制限付き試用（`IsTrial`）**、有料本体、アドオン（トラッキング・ビューア）、日本での自由価格、組織向けの購入 |
| 共通で作るもの | MSIX のビルドスクリプト、Store ライセンスの Rust 共通モジュール | 共通部品をそのまま使う |
| 順序 | **先に公開**（目安 2〜3週間【推測】） | estamp の審査で得た知見を反映してから提出 |

**注意**: 開発者アカウントの発行元名は両方の掲載に表示される。業務ツールの発行元として違和感のない名前（屋号）でアカウントを作ること【推測】。estamp は公開リポジトリのまま出してよいが、LICENSE ファイルを追加すること（MIT と明記する）。
