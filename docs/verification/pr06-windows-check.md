## 1. 準備・ビルド

検証専用のWindows 11 x64通常ユーザーと、依存導入済みのリポジトリを使う。既存の `%APPDATA%\jp.tyaro.estamp` がある場合は勝手に移動・上書きせず、別の検証ユーザーを用意する。既存アプリ・Office文書を終了しない。設定を書き込む試験はこの専用ユーザーだけで行う。

対象コミット／差分、OSビルド、画面解像度、表示倍率、WebView2、Node/Yarn/Rust、Officeの版、EXEのSHA-256を記録。lockを変更せず、ビルド・テストは必ず直列、Cargoは並列2。計測用の2変数を外し、通常releaseを作る。

```powershell
$env:COREPACK_ENABLE_NETWORK='0'
$env:YARN_OFFLINE='true'
Remove-Item Env:VITE_PR05_MEASURE -ErrorAction SilentlyContinue
Remove-Item Env:ESTAMP_PR05_MEASURE -ErrorAction SilentlyContinue
corepack yarn run check
# 各行の $LASTEXITCODE が0であることを確認してから次へ進む
cargo check -j 2 --locked --offline --manifest-path src-tauri/Cargo.toml
cargo test -j 2 --locked --offline --manifest-path src-tauri/Cargo.toml
corepack yarn build
node node_modules/@tauri-apps/cli/tauri.js build --no-bundle -- --locked --offline -j 2
git diff --exit-code -- package.json yarn.lock src-tauri/Cargo.lock
Get-FileHash src-tauri/target/release/estamp.exe -Algorithm SHA256
```

証跡はリポジトリ内の `outputs/pr06-windows/` へ保存し、コマンド出力の拡張子は `.txt` を使う。outputsは追跡しない。共有PCのネットワーク設定・キャッシュ・ツールチェーンを変更しない。表示倍率の変更も他の利用者と調整した検証環境で行う。回線遮断できない場合は「未実施」とし、接続中の確認で代替合格にしない。

### 250×120での通知（レビュー修正）

- 各倍率の通常releaseで、縦スクロールを先頭に戻した250×120のまま印影をクリックする。印影枠の下端に14pxの「○ コピー成功」がスクロールなしで全文表示され、約1.8秒後に消えること。表示中の再クリックとEnter／Spaceもコピーでき、再成功から約1.8秒に表示時間が更新されること。詳細の既存メッセージは下方に残ること。
- 専用の検証環境でclipboard書込みを失敗させる（例：検証用ヘルパーでOpenClipboardを保持）。「× コピー失敗」が枠内に表示され、10秒以上待っても消えないこと。以前のclipboard画像が残っていても今回の成功と誤認しないこと。解放後、通知の上をクリック／キーボードで再試行でき、次の結果に置き換わること。失敗再現条件と実施有無を記録し、単体テストだけで実機合格にしない。
- コピー生成中に印影を変更できる検証条件では「△ コピー中止」を確認。成功・中止はNarratorでpolite、失敗はalert／assertiveで通知され、色だけに依存しないこと。
- 専用ユーザーで設定読込／保存の失敗を再現し、小窓の印影枠上端に「× 設定エラー」が残ること。保存失敗後にコピーが成功してもこの表示が消えず、再読込／保存の復旧で消えること。読込警告は「△ 設定に注意」、書体失敗は「× 書体エラー」で分かり、下方の詳細本文へ到達できること。設定の原本や他ユーザーの権限を変更しない。
- 成功・失敗・設定エラーとの同時表示を撮影し、枠外へのはみ出し、通知同士の重なり、クリック／フォーカス妨害、本番CSP違反がないことを確認する。

- 保存／再読込／旧設定の存在確認と確認付き取込がmainで権限エラーなく動くこと。ソース・生成された `src-tauri/gen/schemas/acl-manifests.json`／`capabilities.json`（生成名は実ファイルを確認）を照合し、main・localのみ、設定4コマンドと画像作成／書込み／解放の7権限で、remote・clipboard読取り・window作成権限がないことを記録する。
- `cargo test` のmainラベル拒否／ローカルorigin限定／IPC保存引数のテストと、JSのcapability／command整合テストが合格すること。別ウィンドウからの実IPC拒否は本PRで試験窓を追加していないため、必要なら検証専用ビルドで別途行い、実施有無を明記する。ソース検査を実IPC試験の合格とは呼ばない。

- 利用を許可されたオフライン検証環境で起動・編集・保存・コピー・ライセンスを確認する。WebView2基盤の通信とアプリ資源要求を区別する。

## 6. PR-06b：案Aの設定展開・入口・長い氏名

専用ユーザーの通常releaseで、100／150／200%それぞれ確認する。既存ユーザーの設定を削除しない。寸法はクライアント領域の論理pxで記録し、タイトルバー・枠を含む外寸と区別する。Windows実機・Narratorの結果は未取得であり、以下は受入手順である。

1. **固定サイズと発見性**: 保存済み設定で起動し、通常250×120、タイトル「電子印 — 右クリックで設定」を確認。歯車がなく、Ctrl+,でも設定が開かないこと。通常時・展開時の両方で枠のドラッグによるリサイズができず、最大化ボタンが無効または非表示で、タイトルバーのダブルクリックでも最大化しないこと。印影のツールチップ・Narratorの名前に「右クリックまたはAlt+Sで設定」を含むこと。トレイは作らない。
2. **右クリックのネイティブメニュー**: 印影、空白、設定内の入力・選択欄、About／ライセンス上で右クリックする。WebView2の既定メニュー（再読込・検証・入力用編集メニューなど）が出ず、OSのネイティブメニューが1つだけ出ること。順序は「設定を開く（Alt+S）」（展開中は「設定を閉じる（Alt+S）」）→「印影をコピー」→「今日の日付に戻す」→「estampについて」→「終了」。矢印・Enter・Esc・Narratorで操作でき、倍率に合った表示であること。コピーは1回だけ行われ、不正入力・変換中などコピー不可時には実行されないこと。「今日の日付に戻す」で手動日付／日付エラーが今日へ戻ること。「estampについて」は既存の設定内Aboutへ展開・移動し、見出しにフォーカスすること。「終了」はアプリを終了すること。
3. **キーボードとフォーカス**: 印影にフォーカスし、Shift+F10とアプリケーションキー（メニューキー）で同じネイティブメニューが1回だけ出ること。ポインターをアプリ外へ置いても、キーボードメニューは窓内に出ること。設定入力中にも試す。Alt+Sで開閉し、開いたときは「印影の設定」見出しへフォーカスすること。見出しが見えている場合は印影を隠す不要なスクロールをしないこと。Esc／閉じる／メニューの閉じるで先頭に戻り、印影へフォーカスが戻ること。閉じた入力へTab移動しないこと。キーの長押しで開閉やメニューを連発しないこと。IME変換中のAlt+S／Esc／Shift+F10が設定の開閉や保存・コピーを起こさないこと。
4. **下へ展開・作業領域・復元**: 通常位置とサイズを記録し、設定を開く。幅250を維持して下へ高さ約560まで広がること。画面下端近くへ移動して開き、現在のモニターのwork area（タスクバーを除く領域）へ収まるだけ上へ移ること。高さ560＋タイトルバー等が入らない検証画面では、上端まで寄せた上で高さを縮め、内部の縦スクロールで全入力・保存・再読込・About／ライセンスへ到達できること。横スクロール・欠けがないこと。左／上側にある負の座標のモニター、倍率の異なる複数モニターでも現在のモニターを使い、タスクバーを覆わないこと。閉じると開く前の位置と250×120へ正確に戻ること。展開中に移動してから閉じても開く前の位置へ戻り、次に開く位置の基準も正しいこと。
5. **左クリックとダブルクリック**: 単クリックは直ちに1回コピーすること。左ダブルクリックは設定を開いて見出しへ移動し、コピーは1打目の1回に留まること（2打目を`click.detail > 1`で抑止、OSのダブルクリック間隔を使用）。コピー生成中と生成完了後の両条件、OSのダブルクリック間隔を長めにした条件でも確認する。Enter／Spaceでは即時に1回コピーし、設定は開かないこと。入力エラー中もダブルクリックで設定へ入れ、コピーは行わないこと。
6. **初回と保存**: 保存先のSetting.jsonが無い状態（loadのrevisionがnull）で起動し、自動で展開・見出しフォーカス・初回入力案内を確認。保存せず閉じると印影の下に「△ 設定が未保存です（Alt+S）」が250×120内で全文見え、ファイルは作成されず、再起動するたび展開すること。初回保存に成功し、編集中の変更・入力／書体／コピーのエラーがなければ自動で畳み、印影へ戻ること。保存失敗、保存待ち中の編集や不正日付、書体／コピーの失敗がある間は自動で畳まないこと。保存済みの通常の保存でも勝手に畳まないこと。明示した閉じる／Escはエラー・未保存中も使えること。
7. **保存後3回のヒント**: 初回保存直後と、その後の1・2・3回目の起動で、印影の下に補助色`#5F6470`の「右クリックで設定」が表示され、4回目以降は消えること。展開中も対象期間のヒントを表示すること。Setting.jsonの任意フィールド`settings_hint_launches`は初回保存時0、以後の初回loadで1→2→3→4（上限4）。同一プロセスの再読込、通常保存、旧設定取込では増減しないこと。フィールドのない有効な旧設定は従来どおり読み込み、今回の起動を1として案内すること。複数起動でrevisionが変わった場合、古い画面からの保存が既存の競合案内で止まること。
8. **旧設定・破損・読込失敗**: 保存先に有効な旧形式があれば自動展開しないこと。EXE隣に旧設定があるだけなら初回扱いとなり、既存の確認付き取込が使えること。取込成功後は初回案内が消え、再起動は畳んだ状態になること。破損退避時は警告を保持して初回扱い、保存せず再起動すると再び展開すること。権限エラー・未対応schemaなどload失敗時は設定を開き、エラーと再読込を示し、保存を止めること。設定の読込／保存結果をNarratorが二重に同文で読み上げないこと（上側は見た目だけ、保存ボタン下の1領域だけ読み上げる）。
